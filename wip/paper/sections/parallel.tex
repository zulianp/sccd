\section{Parallel implementation}
\label{sec:parallel}

\Cref{prop:order} lets the search be explored in any order, and the two
narrow-phase implementations use that freedom in opposite directions: on the
host, vector lanes are filled with work from unrelated queries
(\cref{alg:host}); on the device, work is moved \emph{out} of the block that
generated it (\cref{alg:device}). The broad phase needs no equivalent treatment,
since its parallelism is already the outermost loop of
\cref{alg:cell,alg:cellmin} and its count-then-fill output carries no
contention. Both narrow-phase designs answer the same property of the problem:
CCD query cost is heavy-tailed. \Cref{tab:difficulty} counts, for one scene, the
boxes each query needed; most are decided by a single box and a few need
millions, so any design that pins a query to a fixed execution resource is
load-imbalanced by construction, and not by a factor of two. The design responds
to the host column; the device column sets the size of the tail a work list must
survive (\cref{sec:parallel:device}), but it predates that redesign and
aggregates two code paths, so it supports no host-versus-device conclusion,
which \cref{sec:results:proc} makes under controlled conditions.

\subsection{Host: packing lanes across queries}
\label{sec:parallel:host}

\begin{algorithm}[!tb]
\caption{Host narrow phase. Lanes hold boxes from different queries, which
\cref{prop:order} permits. $V$ is the vector width and $D$ the depth cap.}
\label{alg:host}
\footnotesize
\begin{algorithmic}[1]
\Function{HostNarrowPhase}{candidates $\Cand$}
  \ForAll{blocks $Q$ of $V$ consecutive queries \textbf{in parallel}}
    \State load geometry, $\tau$, $\epsilon$ per query;\;
           $\toi_{q} \gets$ shared minimum
    \State $S \gets$ stack holding the root box of each query of $Q$; all $V$
           lanes idle
    \While{true}
      \ForAll{idle lanes $l$}
        \State pop $\dom$ from $S$, discarding any with
               $\dom.t_{\ell} \ge \toi_{\dom.q}$
          \Comment{refill}
        \State bind $\dom$ to lane $l$, reloading lane geometry only if
               $\dom.q$ changed
      \EndFor
      \State \textbf{if} no lane is live \textbf{then break}
      \State $[\underline{F},\overline{F}] \gets$ hull of the $8$ stored
             corners, per component, all lanes at once
      \ForAll{live lanes $l$}
        \Comment{phase 1: classify, evaluating nothing}
        \If{$\dom_{l}$ is rejected by the test of \cref{eq:err}}
          \State lane $l \gets$ idle
        \ElsIf{\Call{Accept}{$\dom_{l}$} \textbf{or} $\mathrm{depth}_{l} \ge D$}
          \State $\toi_{q_{l}} \gets \min(\toi_{q_{l}},\ \dom_{l}.t_{\ell})$;\;
                 lane $l \gets$ idle
        \Else
          \State $a_{l} \gets \arg\max_{k} \dom_{l}.w_{k}/\tau_{k}$;\;
                 $m_{l} \gets$ midpoint of axis $a_{l}$
          \State \textbf{if} $m_{l}$ does not separate the endpoints
                 \textbf{then} accept and idle lane $l$
          \State \textbf{else} mark $l$ as splitting
        \EndIf
      \EndFor
      \State lay out the $4$ mid-face corner parameters of every splitting lane
      \State evaluate $\Fdiff$ there in \emph{one} vector sweep across all lanes
        \Comment{phase 2}
      \ForAll{splitting lanes $l$}
        \Comment{phase 3: assemble}
        \State push the upper child: the parent's outer face, the new mid face
        \State keep the lower child in lane $l$, overwritten in place
          \Comment{depth-first in $t$}
      \EndFor
    \EndWhile
    \State write $\toi_{q}$ out and lower the shared minimum by compare-and-swap
  \EndFor
\EndFunction
\end{algorithmic}
\end{algorithm}

By \cref{tab:difficulty}, a per-query SIMD kernel would leave most lanes idle, so
the host kernel of \cref{alg:host} takes the \emph{box} as the
unit of work across a vector of $V$ lanes ($V=8$ on AVX-512 and AVX2, $4$ on
NEON). A lane holds a box that may belong to any query and is refilled from a
shared stack once its box is decided, reloading geometry only on a query change;
\cref{prop:order} makes this legal, since the answer is independent of the walk
order. Two design decisions carry most of the performance.

\emph{Each box stores the value of $\Fdiff$ at its eight corners.} A bisection
splits at a mid-face, so the children share that face and each inherits its
outer face from the parent: a split evaluates four corners where one without
inheritance evaluates eight per child, a fourfold reduction in the operation
that dominates the kernel, for a cheap $3\times8$ scalars carried per live box.

\emph{Geometry is replicated per lane.} Since lanes hold different queries,
indexing geometry by a lane's query would make every corner evaluation a gather;
copying the $30$ values a lane needs on refill gives contiguous loads, and a
refill costs far less than the $24$ corner evaluations it feeds.

The iteration has three phases. \emph{Classify} decides every lane's fate from
bounds it already carries and evaluates nothing. \emph{Evaluate} lays out every
lane's mid-face corner parameters and performs one flat vector sweep even though
lanes split different axes, predicating out those not splitting; about half
split per iteration, so this removes roughly a quarter of the kernel's total
work. \emph{Assemble} pushes the upper child to the stack and keeps the
\emph{lower} child in the lane, so each lane is depth-first in $t$: the running
minimum converges sooner and prunes harder, stack traffic halves, and a refill
is skipped.

The two query types peak at different lane widths, since a vertex-face corner
costs one more multiply-add and one more subtraction than an edge-edge corner,
so its sweeps take longer to amortise the per-lane scalar work between them. On
NEON, over the whole scene, narrowing vertex-face from four lanes to two moves
it from $297.7$ to $246.0\,\mathrm{ms}$ and widening edge-edge from two to four
moves it from $599.9$ to $494.6\,\mathrm{ms}$, while eight and sixteen lanes are
worse for both; the x86 widths above follow from the same operation count and
have not been measured. A caveat generalises beyond this kernel: the two types
must be timed in separate processes, since timed together the edge-edge figure
varies by about $20\%$ with the lane width chosen for the \emph{vertex-face}
instantiation, which the measurement never executes. The effect is one of code
layout, not of work, and is large enough to manufacture or conceal a difference
of the size reported here.

\subsection{Device: a small stack, and a queue that redistributes}
\label{sec:parallel:device}

\begin{figure}[htbp]
  \centering
  \resizebox{0.82\linewidth}{!}{\input{tikz/gpu-workflow}}
  \caption{The device narrow phase. Each block keeps a small stack in shared
    memory and spills the rest into one half of a double-buffered global queue;
    a launch writes one half and reads the other, so a producer and its consumer
    always sit in different launches. At the buffer swap the subtree of a
    pathological query becomes available to every block, where a large shared
    stack would have kept it inside the block that seeded it.}
  \label{fig:gpu-workflow}
\end{figure}

\begin{algorithm}[!tb]
\caption{Device narrow phase: a kernel that runs to completion on the work it
was given, and a host loop that relaunches it on what it spilled. $S$ is the per-block shared stack ($64$ entries) and $G$ the
double-buffered global queue.}
\label{alg:device}
\footnotesize
\begin{algorithmic}[1]
\Function{Kernel}{read buffer $G_{\mathrm{in}}$, write buffer $G_{\mathrm{out}}$}
  \State thread $t$ takes one box: its own query's root, or one entry of
         $G_{\mathrm{in}}$
  \While{any thread of the block is live \textbf{or} $S \ne \emptyset$}
    \State refresh the block's bound from the global minimum
      \Comment{every iteration; see text}
    \State \textbf{if} $\dom.t_{\ell} \ge$ bound \textbf{then} idle this thread
    \If{$\mathrm{depth} \ge D$ \textbf{or} $\dom$ cannot be split}
      \State lower $\toi$ to $\dom.t_{\ell}$; idle this thread
        \Comment{exhaustion accepts}
    \Else
      \State $(\dom^{-},\dom^{+}) \gets$ \Call{Split}{$\dom$}
      \State evaluate \textbf{all $8$ corners of each child}
        \Comment{all eight; \cref{alg:host} inherits four}
      \State keep those that contain the origin and can still improve the bound
      \State \textbf{if} both survive \textbf{then} descend into the smaller
             $t_{\ell}$, set the other aside
      \State \textbf{else if} one survives \textbf{then} descend into it
             \textbf{else} idle this thread
    \EndIf
    \If{a box is set aside}
      \State claim a slot in $S$; if $S$ is full, bump-allocate in
             $G_{\mathrm{out}}$
      \State if $G_{\mathrm{out}}$ is full, count the deficit and \textbf{drop}
        \Comment{safe, \cref{sec:guarantee}}
    \EndIf
    \State idle threads claim from $S$ by compare-and-swap, reloading on a
           query change
  \EndWhile
\EndFunction
\Statex
\Function{Host}{candidates $\Cand$}
  \State \Call{Kernel}{seeds, $A$};\quad $r \gets 0$
  \While{the buffer just written is non-empty \textbf{and} $r < 32$}
    \State \Call{Kernel}{it, the other one}; swap; $r \gets r+1$
      \Comment{reader and writer never meet}
  \EndWhile
  \State \textbf{if} the deficit is non-zero \textbf{then} grow $G$ and rerun,
         keeping the times of impact
\EndFunction
\end{algorithmic}
\end{algorithm}

The device kernel runs one thread per query, with its shape in
\cref{fig:gpu-workflow} and its full form in \cref{alg:device}. In each of the
three decisions below the straightforward alternative fails.

\paragraph{The global queue.} The queue is double-buffered: a launch reads one
buffer and writes the other, never both, so there is no producer--consumer
handshake and nothing spins. A single shared buffer, whose writers spin on a
compare-and-swap until a reader releases the slot, \emph{hangs the kernel} once
the queue is driven hard, which is exactly the condition load balancing creates.

\paragraph{The shared stack.} The shared stack is deliberately small, since it
is where a query's subtree lives and a large one keeps a heavy query inside the
block that seeded it: by \cref{tab:difficulty}, one block can work through a
$19.7$-million-box query while its neighbours finish and idle. Spilling early
hands those boxes to the global queue for the next launch to spread over every
block. \Supp{} measures the effect: on cloth-funnel the device narrow phase
falls from $4059.2$ to $37.2\,\mathrm{ms}$ as the per-block capacity drops from
$1024$ to $64$ entries, with false positives and negatives identical at every
capacity, so this is a scheduling result.

\paragraph{Overflow handling.} A box that does not fit in the global queue is
counted and discarded, which is safe since dropping a box can only leave the
reported time of impact earlier than the truth, never later
(\cref{sec:guarantee}). The host reads the deficit, grows the queue and re-runs
the batch, keeping the times of impact found so far so later attempts prune
harder; the retry is bounded at $32$ rounds, since giving up stays conservative
whereas spinning is not finite.

Two smaller decisions were settled by measurement: the running minimum is
re-read from global memory on \emph{every} iteration, since refreshing less
often was monotonically worse on all three scenes tested, the pruning a fresh
bound buys exceeding what the atomic costs; and the unit of work is one thread
per query, which beat one block per query by between $2.76\times$ and
$4.43\times$, because the block-per-query kernel was bound by \emph{scheduling
blocks} and not by the search. The device broad phase is a more conventional
port: count, prefix sum and scatter, with a radix sort and a device scan from
CUB~\citep{cub} for their host equivalents, one box per thread, and a scalar
inner loop where the host uses its $32$-lane mask. Its shape suits a GPU, since
no part of it walks a window sequentially.

\subsection{Precision}
\label{sec:parallel:precision}

Both narrow phases compute in double precision internally whatever type the
caller stores geometry in, and this is a requirement of the method: in single
precision the certified bound of \cref{eq:err} and the tolerances of
\cref{eq:tol} sit too close together for the search to keep its guarantee, and
the single-precision device kernel reported nine times of impact \emph{later}
than the true root on armadillo-rollers, violating \cref{def:conservative}.

The interface stays templated on the storage type, so a caller with float
geometry keeps float buffers. Widening on load is exact, whereas narrowing the
computed time of impact back to float is not: round-to-nearest can round
\emph{up}, publishing a value later than the one the search proved, so the
narrowing rounds toward $-\infty$. Reporting earlier is always safe; reporting
later is the failure the whole design exists to prevent.

\subsection{Why the work divides the way it does}
\label{sec:parallel:why}

\Cref{tab:difficulty} shows the device exploring many more boxes than the host on
the same queries, and \cref{sec:results:proc} shows the device narrow phase
losing to the host on four of six scenes. Both have the same two structural
causes, neither a property of the hardware. The device re-evaluates all eight
corners of both children at every split, where the host inherits four from the
parent (\cref{sec:parallel:host}), a factor on the dominant operation paid on
every box.

The bound a box is pruned against is also probably sharper on the host at the
moment it is needed, a candidate explanation and not an established one: host
lanes descend depth-first in $t$ and publish continuously, so a query benefits
from its neighbours' progress almost immediately, whereas the device walks a far
wider frontier at any instant. The alternatives are easier to rule out than this
explanation is to confirm, since the seeding would show on the easy queries too,
and the acceptance test, the tolerances and the split rule are all transcribed
from the host and would shift the whole distribution uniformly, whereas the
measurement shows a stretched tail. Establishing the remaining explanation
requires a single hard query traced box by box, which we have not done.

The broad phase inverts both arguments, having no sequential dependence and no
shared bound to lose. The GPU accordingly wins that phase on all six scenes, and
the pipeline wins end to end on four of them despite losing the narrow phase on
four. \Cref{sec:results} measures all of it.
