\section{Software and data availability}
\label{sec:availability}

SCCD is released under the BSD 3-Clause licence~\citep{sccd}. The library builds
and its tests run with no external dependencies, no network access and no
configuration:

\begin{quote}
\begin{verbatim}
cmake -S . -B build && cmake --build build -j
ctest --test-dir build
\end{verbatim}
\end{quote}

\noindent
The device kernels, the smesh mesh interface and the TightInclusion accuracy
oracle are opt-in CMake options; the oracle is a validation tool and not a
performance option.

Every table and figure in \cref{sec:results} is generated from a published
measurement file by a published script, and \verb|make inputs| runs all of them;
each table names its own source file beneath it. The tables the article shares
with the library's own benchmark documentation are produced by the same code, so
a number in the two documents has one origin, and a \verb|--check| mode
re-derives the figures the prose quotes from the data and returns non-zero when
they no longer agree. The hardware counters reported in \supp{} are collected by
\texttt{benchmark/scripts/profile.sbatch.sh} and their raw output is published
under \texttt{benchmark/results/profile/}, so no counter is transcribed by hand.

The benchmark scenes, the curated query sets and the exact symbolic roots are
the time-of-impact dataset of \citet{belgrod2025toi}, obtained from the NYU
Faculty Digital Archive~\citep{nyuccd}. TightInclusion~\citep{wang2021tight}, as
distributed in the IPC Toolkit~\citep{ipctoolkit}, is used exactly as released
and is never modified: fairness in the comparison of \cref{sec:results:ref} is
bought by changing our harness to match its configuration, never the other way
round.
