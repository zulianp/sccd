\section{Narrow phase}
\label{sec:np}

Each candidate pair surviving \cref{sec:bp} is decided by branch and bound over
boxes in the parameter domain, on two properties from \cref{sec:prelim}:
\cref{eq:hull} establishes that a box can be judged from its eight corners, and
\cref{eq:err} bounds how wrong that judgement can be. \Cref{alg:np} is the
skeleton every kernel here instantiates; the acceptance test, the split rule and
the work list's organisation vary between them, the last in \cref{sec:parallel}.

\begin{algorithm}[htbp]
\caption{Branch and bound for one query. $\toi$ is the running minimum, shared
across queries when the caller asks only for the earliest impact.}
\label{alg:np}
\small
\begin{algorithmic}[1]
\Function{NarrowPhase}{query, $\toi$}
  \State $\epsilon \gets$ error bound of \cref{eq:err};\quad
         $\tau_{0..2} \gets$ tolerances of \cref{eq:tol}
  \State push $\dom_{0} = [0,\min(\toi,1)]\times[0,1]^{2}$
  \While{a box $\dom$ remains}
    \If{$\dom.t_{\ell} \ge \toi$} \textbf{continue}
      \Comment{a root here cannot improve the answer}
    \EndIf
    \State $[\,\underline{F}_{d},\overline{F}_{d}\,] \gets$ hull of the eight
           corner values, per component \Comment{\cref{eq:hull}}
    \If{$\underline{F}_{d} > \epsilon_{d}$ or $\overline{F}_{d} < -\epsilon_{d}$
        for any $d$}
      \State \textbf{continue} \Comment{\textbf{reject}: the only unsound step,
             so it is padded by $\epsilon$}
    \EndIf
    \If{\Call{Accept}{$\dom$} \textbf{or} $\dom.\text{depth} \ge D$
        \textbf{or} $\dom$ cannot be split}
      \State $\toi \gets \min(\toi,\ \dom.t_{\ell})$;\quad \textbf{continue}
        \Comment{exhaustion \emph{accepts}, never drops}
    \EndIf
    \State push the children of \Call{Split}{$\dom$}
  \EndWhile
  \State \Return $\toi$
\EndFunction
\end{algorithmic}
\end{algorithm}

On acceptance \cref{alg:np} reports the box's \emph{lower} bound in $t$, never its
midpoint or upper bound, and every exit that is not a rejection accepts; these two
facts constitute the safety argument \cref{sec:guarantee} makes precise.

\subsection{The acceptance test}
\label{sec:np:modes}

\op{Accept} and \op{Split} are TightInclusion's test transcribed:
\begin{equation} \label{eq:accept-tight} \textsc{Accept}(\dom) \;=\;
\underbrace{\bigl(\forall d:\ [\underline{F}_{d},\overline{F}_{d}] \subseteq
[-\epsilon_{d},\epsilon_{d}]\bigr)}_{\text{function box inside the error box}}
\ \vee\ \underbrace{\bigl(\forall k:\ \dom.w_{k} \le
\tau_{k}\bigr)}_{\text{\emph{domain} width within \emph{domain} tolerance}} ,
\end{equation} and its split halves the axis furthest past its own tolerance,
$\arg\max_{k} \dom.w_{k}/\tau_{k}$. Starting from $[0,1]^{3}$ makes every midpoint
a dyadic rational, exact in binary floating point while the depth stays below the
significand's width; the implementation relies on none of this, checking that the
midpoint separates the endpoints and accepting the box when it does not.

The test also requires $\dom.t_{\ell} > 0$, refusing a contact at exactly $t=0$
that would otherwise stall a solver using $\toi$ as a step length; measured
against the exact roots it costs nothing, missing no collision and reporting no
late time of impact.

\subsection{Order independence}
\label{sec:np:order}

TightInclusion returns the first box it accepts from a priority queue, so its
answer is the accepted box of globally smallest $t$. \Cref{alg:np} keeps no such
order, and the proposition below establishes that it requires none, thereby
licensing the implementations of \cref{sec:parallel}.

\begin{proposition}[Order independence]
\label{prop:order}
Let $\mathcal{A}$ be the set of boxes that \op{Accept} accepts, over the tree
generated by a fixed \op{Split}. Suppose a search explores that tree in any
order, maintains $\toi = \min\{\dom.t_{\ell} : \dom \in \mathcal{A}
\text{ reached}\}$, and skips any box with $\dom.t_{\ell} \ge \toi$. Then on
termination $\toi = \min\{\dom.t_{\ell} : \dom \in \mathcal{A}\}$, independent of
the exploration order.
\end{proposition}

\begin{proof}
Let $m$ be the right-hand side and $\dom^{\ast}$ a box attaining it. Since $\toi$
only ever takes values $\dom.t_{\ell}$ for reached $\dom \in \mathcal{A}$, we
have $\toi \ge m$ throughout. For the converse, suppose $\dom^{\ast}$ is skipped.
It is skipped only because $\dom^{\ast}.t_{\ell} \ge \toi$ at that moment, and
$\toi \ge m = \dom^{\ast}.t_{\ell}$, so $\toi = m$ already. Otherwise
$\dom^{\ast}$ is reached and $\toi \le \dom^{\ast}.t_{\ell} = m$. The same
argument applies to every ancestor of $\dom^{\ast}$: an ancestor is pruned only
when $\toi$ has already reached a value at or below its $t$ lower bound, which is
at or below $m$. Hence $\toi = m$ in all cases.
\end{proof}

\begin{remark}[Agreement with the reference]
\label{rem:ti}
TightInclusion's answer is the same minimum, so the two agree exactly. Its queue
is ordered by ascending $t$ lower bound, so the first accepted box it pops has the
smallest $t$ lower bound among accepted boxes it \emph{reaches}; and a box it
does not reach was pruned by the same $t$ bound, which by the argument above is
already at or below that minimum. Hence its answer is
$\min\{\dom.t_{\ell} : \dom \in \mathcal{A}\}$, the same quantity
\cref{prop:order} gives.
\end{remark}

The hypotheses of \cref{prop:order} carry weight: fixing \op{Accept} and
\op{Split} fixes $\mathcal{A}$, and two searches agree only when they generate the
same $\mathcal{A}$, which requires the same acceptance \emph{rule} and the same
computed values feeding it, down to the last bit. Our host kernel and
TightInclusion meet that condition, its corner evaluation written in the
reference's expression order precisely so that they do (\cref{sec:prelim:err}),
and \cref{sec:results:ref} confirms the consequence to every printed digit on all
twelve scene-phases. Our \emph{device} kernel does not: it evaluates the same
formulas through vector fused multiply-adds and rounds $\delta^{3}$ upward with a
plain cube, so a box decided in the last few units in the last place can fall
differently and its $\mathcal{A}$ differs slightly. \Cref{prop:order} thus
accounts for the host reproducing the reference while leaving the device's
agreement with it open, and \cref{sec:results:ref} measures the device separately
and finds it close without being identical.

The proposition grants freedom in how the tree is traversed: depth-first,
breadth-first, or interleaved across queries, with boxes from unrelated queries
sharing a vector register or a thread block and work migrating between processors
mid-search. None of that can change the answer, and the two implementations in
\cref{sec:parallel} exploit this freedom in different ways.

\subsection{Quads}
\label{sec:np:quad}

Quad meshes are handled directly, without triangulation: they have their own
inclusion function (\cref{eq:fvq}), their own tolerance and error reductions,
their own host root finder and their own device kernel, implemented separately
from the triangle kernel, which is built end to end around a four-point query
packed into one vector register on a barycentric domain --- a vertex-quad query
has five points on an independent domain, so the load, the tolerances, the error
bound, the corner evaluation, the domain test and the split would all have to
change at once. That kernel cuts an axis at two interior points into three
children at once, each clamped to within a bounded fraction of its nominal
position, where the triangle kernel halves one axis. The path is \emph{not evaluated} in this paper, since every scene
in \cref{sec:results} is a triangle mesh and the error constant of
\cref{sec:prelim:err} for the bilinear form is uncertified; what follows is a
design verified for correctness against a densely sampled reference root, and not
a measured result. The evaluation is factored $\Fdiff = q(t) - \sum_{k}
w_{k}(u,v)\,g_{k}(t)$, since the weights do not depend on $t$, so a split along
$u$ or $v$ holds the $t$-dependent frame fixed across every corner it evaluates;
and the node order in \cref{eq:fvq} is lexicographic, since winding the nodes
around the quad swaps the last two, after which the solver searches a bilinear
saddle across the diagonal and reports a valid time of impact for a surface the
caller did not mean --- a silent failure, so the convention is recorded here.

One measurement from the quad path generalises. Hoisting the split-plane
evaluation out of the loop over children, the textbook optimisation, is
$1.3\times$ faster per isolated query and $1.35\times$ slower end to end, since
$\toi$ sharpens \emph{during} the loop and a child whose $t$ lower bound has since
passed the running minimum is discarded unlooked-at while hoisting evaluates it
anyway: when the bound is shared, a syntactically loop-invariant computation is
not invariant in the work it performs.
