# The SCCD article

A self-contained LaTeX preprint on SCCD's algorithms, parallel implementation
and accuracy assessment against TightInclusion.

```sh
make          # main.pdf
make check    # cross-check the prose's numbers against the generated tables
```

`make` needs a TeX Live with `natbib`, `algorithm`, `algpseudocode`, `booktabs`,
`cleveref` and `tikz` — all of them standard — and nothing else. No network, no
Python, no plotting stack.

## Where the numbers come from

Nothing numeric in `sections/` is typed by hand where a table has it. The tables
under `generated/tables/` are produced by `scripts/make_inputs.py`, which calls
the same `benchmark/report` package that generates `docs/BENCHMARKS.md`, with the
same mode selection and the same call sequence — so a figure here and the same
figure in the library's documentation have one origin, the committed CSVs under
`benchmark/results/`.

```sh
make inputs   # regenerate generated/tables/ after a new sweep
```

The hardware-counter table is built the same way, by `scripts/make_counters.py`
from `benchmark/results/profile/` — Nsight Compute CSV for the Hopper kernel and
`perf stat` output for Grace. `benchmark/scripts/profile.sbatch.sh` is the job
that produces those files on Alps.

That step needs only the standard library: `benchmark/report` imports matplotlib
lazily, so the table half runs on a machine with no plotting stack. Drawing the
figures does need matplotlib and numpy — see `benchmark/scripts/venv.sh` — which
is why the five figures are committed here as PDFs, copied from `docs/figures/`.
They are regenerated by the library's own report command, not by this directory.

`scripts/make_figures.py` draws the two figures the library's own report does
not: the strong-scaling plot from `benchmark/results/profile/strong-*.csv` and
the per-frame plot from the sweep CSV. It is the one script here that needs
matplotlib, which is why its output is committed as PDF and `make` never runs it.

`make check` verifies three things: that each figure quoted in the prose still
appears in the table it cites, that the totals the prose states are still the sums
of the columns they come from, and — the one that matters most — that every
generated table is **row-for-row identical to the corresponding block of
`docs/BENCHMARKS.md`**. That is a stronger claim than "both came from the same
CSV": it means a reader of the paper and a reader of the documentation are looking
at the same table.

## Review

`REVIEW.md` holds a referee report written against an earlier draft and a
point-by-point record of what changed in response. Two of its findings were
substantive: the broad-phase conclusion in the results section did not follow from
its own table, and the closest prior work is cited but never compared against.

## What a co-author would need to supply

A scene-overview figure — one render per scene, in the style of the dataset
paper's Figure 4.1 — is the one thing the repository cannot produce, since it
holds simulation frames but no renderer. The paper reads without it.

## Layout

| | |
|---|---|
| `main.tex` | Title block, packages, notation, section wiring. |
| `arxiv.sty` | The preprint style, vendored. Nothing is downloaded. |
| `sections/` | One file per section. |
| `tikz/` | The two hand-drawn schematics. |
| `figures/` | The five measured figures, copied from `docs/figures/`. |
| `generated/tables/` | One `.tex` per table, built from the committed CSVs. |
| `scripts/make_inputs.py` | Builds `generated/`, and `--check`s the prose. |
